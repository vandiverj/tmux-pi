# Explicit adaptive goal mode (cooperative; not a sandbox)

Source alignment: `Documents/AgentThoughts/plans/tmux-pi-codex-goal-source-analysis.md` (pinned `openai/codex@9ef9cb1`). This implementation keeps the **full original objective** across adaptive main Orient/Frame turns; it does not define success by fixed hashes or milestones. Goal records live in `<project>/.tmux-pi/goals/` under an advisory lock with fsynced atomic replacement. A spec or skill is never authority.

## Start and operate

Write JSON with `id`, `objective`, `done`, `scope`, `workdir` (canonical absolute project directory), `allowed_paths` (project-relative path prefixes for edit attempts) and `budget` (`seconds`, `turns`, `tokens`, `cost_micros`, `attempts`, all positive). Example: `{"id":"parser","objective":"Fix parser behavior and regressions","done":"All parser requirements and tests verified with independent review","scope":"Only the parser and its tests","workdir":"/absolute/project","allowed_paths":["src","tests"],"budget":{"seconds":3600,"turns":20,"tokens":100000,"cost_micros":1000000,"attempts":10}}`. Without `allowed_paths`, goals cannot authorize edits.

`bin/tp-goal --project /absolute/project plan --spec /path/spec.json` only writes a **non-authorizing proposal**. Separately inspect/approve the exact scope/workdir/budget, then explicitly start it with `bin/tp-goal --project /absolute/project start parser --confirm START-GOAL --approve-sha256 <plan.spec_sha256>`. This is a cooperative human approval, not authentication. In that project's main Pi session `/goal attach parser` emits one goal-tagged main turn; `dispatcher.ts` validates the live ticket and spec before routing and **before follow-up classification**, forces main to make a fresh R5 Orient/Frame contract, and checks each delegated attempt against deterministic goal policy (allowed paths, no high-risk/trust/consequential actions, mandatory opposite-provider review). Laya chooses model/effort only. Approved goal continuation is distinct from pending automatic routing cells; `/auto off` still refuses it. The worker receives the original objective and scope alongside its specific contract. Direct-main goal edits are blocked.

The dispatcher durably links the spawned author and later the opposite-provider reviewer. Their reporter usage is charged by stable task ID; only binding `review-required.json` approval and canonical `tp-contract collect` permit a next turn. A verified live tmux task pane is polled without restarting it. A main reply ends with `GOAL_REPORT: {"outcome":"progress|wait|no_progress|safety_block|complete","evidence":"current authoritative evidence","blocker":"same blocker key or linked task id"}`. Ordinary same-blocker no-progress stops after three turns; safety/trust/policy/unknown-handle blocks immediately. `complete` requires the model's full-objective evidence audit, no unlinked tasks or unresolved handoff markers, and valid independent review plus collection for every linked author; it **does not** grant release/deploy/push authority or prove an unchecked claim. Current acceptance evidence is cooperative model reasoning and reviewer verification, not an OS-level acceptance suite.

`tp-goal --project ... status parser` inspects state. `pause parser --reason '...'` and `stop parser` prevent future admissions but do not silently kill a live worker; `resume parser --confirm RESUME-GOAL --diagnosis '...'` requires a human and remaining budget. A worker's tool-error escalation is **not** an automatic goal continuation: before a target pane starts, escalation pauses the goal for a human to authorize a fresh bounded R5 attempt. It never copies a source goal ticket into a new unmetered worker. Missing reporter usage or a changed review invalidates progress. Wall time starts at approval, even during pauses. Limits stop **new admissions**, not already-running work; existing task contracts enforce their own bounded budgets. No external writes, new MCPs, destructive changes, dependency installation, push/deploy/release or trust approval are implied by goal start. Existing R5 cooperative boundaries apply; unrestricted post-contract shells are not an OS sandbox.

## Restart and limits

Session reload restores only the goal attachment. A persisted in-flight main ticket is **unknown**, not evidence a turn is still live: goal state suspends, never replays or re-spawns it. After checking authoritative handles and ensuring no live/unlinked worker exists, a human may `resolve parser --confirm RESOLVE-GOAL-TURN --evidence 'observed cancellation proof'` and separately resume. A known live linked task may continue being polled; if the dispatcher watcher is lost **before** it records review approval, goal mode does **not** forge approval or silently reattach that watcher: the goal suspends for human review reconciliation. An already-approved linked task may still be canonically collected. Reviewer unavailable, stale/unknown evidence, capability/trust prompts, or inability to meter descendants stop continuation.
